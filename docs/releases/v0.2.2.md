# Arelis v0.2.2 — patch notes

Built over one sitting on top of 0.2.1. Checkout data stays in the repo;
installed profile stays `%LOCALAPPDATA%\Arelis`. This release does not copy one
into the other.

The headline is unglamorous: the app stopped launching, silently, and the work
of this release is as much about making a silent death impossible to hide again
as it is about the features that shipped beside it.

---

## The app would not open, and said nothing about why

A stray edit while wiring the glass tabs dropped a `self._style_dock_tabs()` call
between the `if checked:` body and its `else:` in `MainWindow._toggle_camera`, so
`arelis/ui/app.py` no longer parsed. The whole UI module failed to import, and
because the desktop shortcut launches `pythonw.exe -m arelis` — a GUI-subsystem
binary with no console — the `SyntaxError` went to a stderr nobody was reading.
The visible result was a shortcut that did nothing.

The fix to the syntax is one line moved. The fix that matters is the one that
turned "the process just vanished" back into a traceback:

- **`logging_setup.install_unhandled_hook()`**, called from `main()`, routes any
  uncaught exception to `logs\arelis.log` before the interpreter tears down.
  `pythonw` has no console for `sys.excepthook` to write to, so without this a
  crash at import is invisible. This is what named the `SyntaxError` on the first
  relaunch after it was added.
- The log is UTF-8 and rotates, and the console handler is only attached when
  `stderr` is a real tty, so a windowless launch is not quietly throwing its own
  diagnostics away.

`tests/test_logging_setup.py` pins that a turn failure and an uncaught exception
both land in the file.

## Consoles stop flashing over the glass

Tesseract, git, the PowerShell GPU probe and the `schtasks` query at launch all
allocate a console on Windows, which flashed a black `cmd` box over the
translucent UI — including on OCR (7.5) and on `/role code`.

`arelis/hidden_proc.py` installs a process-wide wrap of `subprocess.run` that adds
`CREATE_NO_WINDOW`, set once from `main()`. `ARELIS_SHOW_CONSOLES=1` opts out.

Two deliberate non-choices, both learned the hard way and pinned by
`tests/test_hidden_proc.py`:

- **`Popen` is left untouched.** An earlier attempt subclassed `subprocess.Popen`
  and took the whole `pythonw` process down on the first child — the Task
  Scheduler query during UI start — with no traceback. Direct `Popen` callers
  (her browser, ComfyUI) keep their own flags.
- **No `STARTUPINFO`/`SW_HIDE`.** Combined with `CREATE_NO_WINDOW` it has returned
  `ERROR_INVALID_PARAMETER` on some Windows/Python pairs. `CREATE_NO_WINDOW`
  alone is enough.

## Glass tabs and lists are ember, not Windows grey

Windows ignores translucent QSS on a native `QTabBar` and `QListWidget` and paints
its own grey chip through the glass. The History/Camera dock tabs, the Settings
tabs and the Settings → Roots list all showed grey where they should have shown
amber-on-ember.

- The dock tab bar and the Roots list (`objectName="SettingsList"`) get opaque
  ember fills (`theme.py`: `raised`, `well`, `tab_selected`) plus a Fusion
  `QStyle`, which repaints the selected tab instead of deferring to the native
  theme.
- **A `QStyle` set with `QWidget.setStyle` is not owned by the widget.** The
  first pass created a local Fusion style that was garbage-collected when the
  method returned, and the next paint walked a freed pointer — a native crash in
  `pythonw` with no Python traceback. The style now lives on the window
  (`self._dock_tab_style`) and dialog (`self._fusion_style`), parented so it
  cannot be collected out from under a paint.
- The dock is restyled after layout restore recreates its bar, and the tab labels
  no longer elide to `hist…`/`cam…` — short names get their full width.

`tests/test_visual_consistency.py` guards that these surfaces carry opaque ember
tokens rather than translucent QSS.

## "Email me" goes to your inbox

"Email me the …" now resolves the recipient to *your* inbox — `user.email` in
`profile.yaml`, or `email.default_recipient` in `secrets.yaml` — not the Gmail
address Arelis sends *from*. If neither is set she asks rather than mailing her
own account. Covered by `tests/test_email_complete.py` and `tests/test_email.py`.

## ComfyUI is parked when it is not needed

Image generation leaves a large model resident on the graphics card. Comfy is now
parked after it produces an image and before a heavier chat model needs the VRAM,
so a generate does not starve the next research turn. `arelis/llm/vram.py` and
`arelis/tools/comfy_lifecycle.py`, pinned by `tests/test_vram_guard.py` and
`tests/test_comfy_lifecycle.py`.

## Browser routing that does not guess

- Opening `youtube.com` while the tab is still on a `/results?search_query=…` page
  navigates to the home page rather than treating results as home.
- "go to sign in" / "sign me in" / "take me to the login" (and the one-word "go to
  signin") take a snapshot and click the real header control behind an Allow card,
  instead of navigating to a guessed `/account_signin` URL. Unknown `goto_*` /
  `sign_in` actions fall back to a snapshot. Password and OTP walls still freeze
  the drive — she does not type the password. `tests/test_browser.py`,
  `tests/test_routing_hardening.py`.

## Smaller, and quieter

- The thinking line and the parked-orbit shimmer no longer pop in and out during a
  turn; they hold for the whole wait (`ui/void_idle.py`, `ui/panels/conversation.py`).
- The composer caret and the parked-orbit gutter use real `contentsMargins` rather
  than CSS `padding-right`, which does not inset the HTML "you" bubbles.
- Scheduling: a briefing can be forced, the `run_now`-on-confirm echo is hidden,
  and a new job's id is surfaced in `[square-brackets]` (`core/agenda_complete.py`,
  `tests/test_agenda_complete.py`).
- Preflight and plan-nudge hardening for research / weather / send routing
  (`core/preflight.py`, `core/plan_nudge.py`, `core/agent_loop.py`).
